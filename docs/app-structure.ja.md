# アプリの組み立て

[English](app-structure.md) · [README](../README.ja.md#資料)

lamina-ui のプログラムがどう動くかを書きます。窓とその繰り返し、受け取る入力、部品のあいだで入力・フォーカス・読み上げを振り分ける仕組みです。いちばん小さなプログラムは [README](../README.ja.md#いちばん小さなプログラム) にあります。

## ターゲットと入力のイベント

ライブラリは CMake のターゲット三つに分かれていて、`src/` の下にターゲットごとのフォルダーがあります。バックエンドの別名 `lamina::thorvg` と `lamina::sdl3` はそのまま名前空間の名前で、本体の名前空間は `lamina` です。`src/lamina/` は本体（`lamina::lamina`：トークン・色・描画面の口・文字・図形・レイアウト・入力のイベント・部品）で、SDL3 も ThorVG も使いません。`src/lamina_thorvg/` は ThorVG で描く描画面（`lamina::thorvg`）、`src/lamina_sdl3/` は窓・設定のフォルダー・OS のフォント（`lamina::sdl3`）です。二つのバックエンドは本体だけに依存し、互いには依存しません。部品はポインター・キー・文字の入力とクリップボードを `lamina/input/`（`lamina::input`）の形で受け取り、それを作るのは SDL3 の窓です。`input::Key` には編集用のキー・英字・数字と、`+ - * / . % = ( ) ^ !` の文字のキーと、スペースキー（`Key::space`）があります。スペースキーは窓が Enter と同じく名前のあるキーとして知らせるので、`key_for_character` は空白の文字を割り当てません。Page Up と Page Down（`Key::page_up`・`Key::page_down`）もあります。`input::WheelEvent` はポインターの位置でのマウスホイールの回転で、単位はノッチです（タッチパッドでは端数になります）。`dy` が正なら終わりの方へ、`dx` が正なら右へ送ります。OS がホイールの向きを逆にしている設定でも同じです。窓はこれを `Frame::wheel` に集めます。窓は文字のキーを、そのときの Shift の状態で打たれる文字で知らせます（`input::key_for_character`）。そのため `*` は、US 配列では Shift+8、日本語配列では Shift+: です。テンキーからも同じキーになります。文字のキーは文字入力を始めずにキーのイベントとして届くので、かな入力の IME に取られません。逆向きに、英字・数字・文字のキーからその文字を得るのが `input::character_for_key` です（英字は小文字になります）。`KeyEvent` は Shift・Ctrl・Alt の状態（`shift`・`ctrl`・`alt`）を持ちます。Ctrl+Alt は配列によっては AltGr なので、Alt も押されているあいだ `ctrl` は立ちません。`PointerEvent` は、マウス・指・ペンのどれから来たか（`kind`）を持ちます。窓は SDL の指とペンのマウス番号から決めます。`PointerEvent::waiting_scrollers` は、部品のまわりで指のなぞりが遊びを越えるのを待っているスクロールの軸を表します。内側のスクロールは、それと合わない角度のなぞりを手放せます。`PointerEvent::margin_claimed` は、ほかの部品がその点をタッチの範囲で取ったことを表します。そのとき部品は、自分の見た目の範囲だけで判定します（[タッチの範囲](design-tokens.ja.md#タッチの範囲)）。本体の中では、`tokens/` が値を入れる先のモジュール（`motion::SpringSpec`・`text::TextStyle`・`color::Role`・`render::CornerRadii`）に依存し、`motion/`・`text/`・`color/`・`render/` は `tokens/` に依存しません。

## 繰り返し

`lamina_sdl3/app.hpp`：`run_app` がその窓でフレームの繰り返しを回します。毎フレーム、フレームの情報（入力・大きさ・経過時間）を渡して `update` を呼び、`update` が返す背景色で描画面を塗りつぶして dp の縮尺に合わせ、`paint` を呼んで描かせてから画面に出します。`paint` はまだ動いているものがあるかどうかを返し、何も動いていなければ次のフレームはイベントを待ちます。なので `update` は、入力を処理したあとにもう一度配置をします。`Label::set_text` のように中身を変える処理は、次の配置で測り直す印を付けるだけです。何も動かないままフレームが終わると、次のイベントまで古い中身が出たままになります。押す・離す・外へ出るの三つが一つのフレームに届くタッチのタップがそうで、押下とホバーの層が動き始めません。ギャラリーと文字欄の例は、入力の前とあとの両方で配置をします。Windows では、窓の枠をドラッグしている間、システムの中で別の繰り返しが回ります。そのため、イベントを取り出して回すだけの繰り返しでは、マウスを離すまで描き直されず、離したときに配置が新しい大きさへ飛びます。`run_app` は、ドラッグ中に SDL が送る大きさ変更中の再描画のイベントごとにも、入力なしで 1 フレーム描きます（`Window::on_live_resize`）。そのため、中身が枠に合わせてついてきます。窓を `WindowOptions` と描画面から作る形と、作ってある `Window` を受け取る形があり、コールバックの中で窓を使うとき（クリップボード、`set_text_input`、`wake_after`）は後者を使います。`run_app` は例外を捕まえません。例外は呼び出し側に届き、報告のしかたは呼び出し側が決めます。フォントの読み込みのように繰り返しの前の準備で起きた例外も、同じ処理で扱えます。自分で繰り返しを書くときは、これまでどおり `Window` の関数をそのまま使えます。

## 窓

`lamina_sdl3/window.hpp`：描画面を映す SDL3 の窓。ポインターの位置を dp に直し、何も動いていない間はイベントを待って止まります（`lamina::sdl3`）。1 フレームの時間の刻みは 0.1 秒までですが、`wake_after` で頼んだ待ちの後だけは、待った時間をそのまま刻みに含めます。そのため、テキストフィールドのカーソルの点滅のように `step` で数える時間は、窓が止まっている間も進みます。窓は ThorVG に依存しません。描く先の描画面を `std::unique_ptr<render::Canvas>` で受け取り、毎フレーム `Canvas::resize` で窓の画素の大きさに合わせ、`Canvas::finish` が返す画素を 32 ビットの ARGB として画面に送ります。そのため、ARGB の画素に描く描画面であれば何でも差し込めます。`set_size(width, height)` は窓の中身の大きさを dp で変えます。最大化しているときは先に元に戻します。`set_minimum_size` は、利用者が枠を引いてそれより小さくできない大きさを dp で決めます。どちらもコンストラクターと同じく表示の倍率で dp を換算します。`set_always_on_top` は窓をほかの窓より手前に保ちます。`native_handle` は、OS ごとのコードのために、Windows では窓の `HWND` を返します（ほかの OS では null）。見本は `examples::window_canvas()`（`examples/common/canvas.hpp`）が作る ThorVG の描画面を渡しています。`Frame::safe_area` は、システムのバーや画面の切り欠きがかからない窓の部分を、SDL の安全な領域から dp の余白として表したものです。デスクトップでは 0 です。換算（`safe_area_insets`）と `inset_rect` は `lamina/layout/safe_area.hpp` にあり、見本はその内側に配置します。

## 描画面

`lamina/render/canvas.hpp`：曲線・角丸の四角・影・座標変換の積み重ねを持つ 2D の描画面。描くのは ThorVG です（`lamina::thorvg`）。ThorVG を選んだ理由は [docs/renderer-comparison.ja.md](renderer-comparison.ja.md) にあります。`fill_rect` はただの四角を塗り、バックエンドごとに実装します。ThorVG の描画面は `appendRect` を使わず、四角の曲線と同じ輪郭を渡します。ThorVG は軸にそろった4つの角の輪郭をなめらかにせずに塗るので、縁が変わってしまうためです。`draw_image(image, rect, opacity)` は `render::Image`（`render/image.hpp`：幅・高さと、行ごとに並べた ARGB の画素。アルファは乗算済みでないもの）を四角いっぱいに引き伸ばして描きます。座標変換とクリップに従い、不透明度は 0 から 1 です。Compose の `DrawScope.drawImage` に描き先の大きさとアルファを渡したときと同じです。ThorVG の描画面は呼ばれた時点で画素を写し取るので、画像を描画の終わりまで残しておく必要はありません。拡大縮小はバイリニアで補間します。`push_clip` は四角のほか任意の曲線も取ります。Compose の `Modifier.clip(shape)` と同じで、画像を Material の形に切り抜けます。`pop_clip` は最後のクリップを終え、クリップは入れ子にできます。`render/geometry.hpp` には点の計算（`+`・`-`・拡大・`length`・`unit`・`left_normal`・`cross`）と `circle_rect` があり、`render/path.hpp` は角丸の四角、枠線のための輪（`ring_path`）、円（`circle_path`）、点の列に沿って両端の丸い線の輪郭（`stroke_path`）を作ります。描画面は塗ることしかできないので、線もこの輪郭で塗ります。

## カーソル

`input::Cursor` と `sdl3::Window::set_cursor` はシステムのカーソル（矢印・文字・指・横と縦の大きさの変更・移動・禁止）を設定します。カーソルを求める部品は `cursor()` で知らせます。`input::WheelEvent::shift` は Shift を押していたかを表します。`input::Key` には F1〜F12・Insert・メニューキーと、Alt だけを押して離したときに窓が知らせる `Key::alt` もあります。`PointerEvent` は押したときと離したときの Shift と Ctrl を持ち、右ボタンを押したことは `Frame::context` の `input::ContextClick` として届きます。

## タイトルバー

`lamina/widgets/title_bar.hpp`・`lamina/input/caption.hpp`・`WindowOptions::client_title_bar`：Windows で lamina が自分で描くタイトルバー（選んだときだけ使います）。題名・アプリの部品・最小化・最大化（元に戻す）・閉じるのボタンを描き、ドラッグでの移動・スナップ・大きさの変更・影は Windows に任せます。`client_title_bar` を頼まない窓は OS の枠のままです。Windows 以外や、`LAMINA_CLIENT_TITLE_BAR=OFF` で組み立てたときは、頼んでも OS の枠になります。components・navigation・電卓・タイマー・ToDo リストの例は `--title-bar` を受け付けます。詳しくは [docs/custom-title-bar.ja.md](custom-title-bar.ja.md) を見てください。

詳しくは[自前で描くタイトルバー](custom-title-bar.ja.md)にあります。

## 設定のフォルダー

`lamina_sdl3/resources.hpp`：`preference_directory(organization, application)` は、プログラムが自分のファイルを置いてよいフォルダーを返します（`SDL_GetPrefPath`。フォルダーがなければ作ります。Windows では `%APPDATA%\<organization>\<application>\` です）。得られないときは SDL の理由を添えたエラーを投げます。

## 部品に共通する形

`lamina/widgets/protocol.hpp`：部品に共通する形を、できることごとに一つずつ C++20 のコンセプトで表します。`Paintable` は `paint(canvas, scheme)` を、`Steppable` は `step(dt)` と `animating()` を持ちます。`HandlesPointer`・`HandlesKeys`・`HandlesText` はその出来事を受け取る `handle` を持ち、その戻り値は部品ごとのまま（`bool`・`MenuResponse`・`DialogResult`）です。`Cancellable` は `cancel_interaction()` を持ちます。`HoldsPointer` は `holds_pointer()` を持ち、部品がいまの押下を持っている間（引きずっているスライダー、開いているメニュー）は true を返します。そのとき、まわりのスクロールする範囲は指のなぞりを引き取りません。`Targeted` は `target_hit(event)` を持ち、部品の 48 dp のタッチの範囲にどう当たったかを返します。`WidgetSet` と小さな部品をまとめる部品は、これを使って、範囲の重なるところではいちばん近い部品に点を渡します。大きさについては、`Sized` が `width()`・`height()`・`set_origin` を、`WidthSettable` はさらに `set_width` を持ちます。`SizeSettable` は `set_size(width, height)` を足したもので、`Button` が持ちます。`Measurable` は `measure(constraints)` と `arrange(rect)` を持ち、`Label`・`TextField`・`NavigationRail` がこれに当たります。`nodes.hpp` の `widgets::node(w)` は、これらに対する一つの変換です。`Measurable` な部品は自分で測って自分を置きます（入力欄は自分の幅のまま、左上に置かれます）。そうでなければ、`WidthSettable` な部品は幅いっぱいを取り、`Sized` な部品は自分の大きさのままで、どちらも上下の中央に置かれます。`centered_node`・`full_width_node`・`measured_node` を使えば、置き方を直接選べます。`filled_node` は `SizeSettable` な部品に、置かれた四角形をまるごと与えます。`node` はこの置き方を選ばないので、ボタンは頼まない限り自分の大きさのままです。どの部品がどのコンセプトを満たすかは、テストの `static_assert` で確かめています。

## WidgetSet

`lamina/widgets/widget_set.hpp`：`WidgetSet` は `Paintable` な部品を種類を問わずまとめて持ち、`Steppable` なものを進め、全部を加えた順に描き、どれかが動いているかを返します。そのため `Label` もセットに入れられます。`add(widget)` はよそにある部品を参照し、`emplace<W>(args...)` は部品をセットの中に作って、ずっと有効な参照を返します。`cancel_interaction()` はこれを持つ部品に伝えます。`add(widget, on_result)` と `emplace_with<W>(on_result, args...)` は受け手の関数も受け取ります。`handle(PointerEvent)` と `handle(KeyEvent)` は、その出来事を受ける部品すべてに渡し、部品自身の戻り値でその部品の受け手を呼びます（受け手は部品も受け取れます：`(W&, const Result&)`）。戻り値が出来事を使ったと示すとき（`true`、または `consumed`）に true を返します。`remove(widget)` は部品をセットから外し、セットの中に作った部品は壊します。セットが部品を順にたどっている最中に外しても安全で、その部品自身の受け手から外してもかまいません。外した部品はそれ以降飛ばされ、いちばん外側のたどりが終わったときにセットから抜けます。たどっている最中に加えた部品は、次のたどりから対象になります。`for_each<W>(f)` は型が `W` の部品を順にたどり、同じ決まりに従います。`contains(widget)` は部品がセットにあるかどうかを返します。`handle(TextEvent)` は文字を受ける部品に文字を渡し、`set_enabled(bool)` は無効にできる部品（`Disableable`）をまとめて有効・無効にし、`accessible_nodes()` は部品の読み上げ用の節点を集めます。それ以外のことはしません。入力の行き先を決めるのはプログラムで（下の `OverlayStack` と `FocusManager` を使えます）、配置もプログラムが行います。セットを複数持てば、その間に別のものを描けます。ナビゲーションの例では、ページの部品とメニューの間にレールのボタンを描いています。

## 重なるもの

`lamina/widgets/overlay_stack.hpp`：`OverlayStack` は、メニューやダイアログが開いているときの入力の行き先を決めます。`add_base(widgets...)` には、どの重なりよりも下にあるものを渡します。`Cancellable` なものなら何でもよく、`WidgetSet` も渡せます。`Overlay` は `is_open()`・ポインターとキーの `handle`・`cancel_interaction()` を持つ部品で、`Menu`・`GroupedMenu`・`Dialog` がこれに当たります。プログラムはそれを開いたあとに `push(overlay, on_result)` を呼びます。モーダルな `push`（既定）は、先に、すでに開いている重なりと下にあるものの操作の途中を取り消します。そのため、メニューを開いたボタンからはマウスを乗せた状態が消えます。`handle(event)` は、ポインター・キー・文字の出来事を、開いている重なりのいちばん上に渡します。`on_result` がその部品の戻り値の型を受け取れるときは、それを渡して呼びます（メニュー・ダイアログ・スナックバーは、ポインターとキーのどちらにも同じ型の `MenuResponse`・`GroupedMenuResponse`・`DialogResult`・`SnackbarResponse` を返すので、一つの関数が両方を受け取ります）。出来事がそこで止まるときは true を返します。モーダルな重なりなら必ず止まり、モードレスな重なり（`Modality::modeless`）なら、戻り値が出来事を使ったと示すとき（`true`、または `consumed`）に止まります。止まらなければ、出来事はその下の重なりに進みます。`handle` が false を返したら、プログラムが下にあるものに渡します。閉じた重なりは、閉じるきっかけになった出来事のすぐ後に、自分でスタックから外れます。`set_focus(focus_manager)` を呼んでおくと、モーダルな `push` は下にある部品からキーボードのフォーカスを取り上げ（`FocusManager::suspend`）、その重なりが外れるときに、もとの部品に返します（`resume`）。その部品が順から外れていたり、フォーカスを受けられなかったりするときは返しません。ポインターで押して閉じたときも返しません。押すことでキーボードのフォーカスは終わるので、覚えていた部品を忘れます（`discard`）。重なりが重なっているときは順に返し、同じ重なりをもう一度 `push` しても二重には取り上げません。メニューもこの扱いを受けます。`remove(overlay)` は、開いていても閉じていても重なりをスタックから外し、閉じたときと同じようにフォーカスを返します。`handle` の最中に受け手の関数から呼んだときは、その出来事が終わったときに外れます。描くのはプログラムの側なので、閉じかけのメニューは描く順のまま消えていきます。ナビゲーションの例は、二つのメニューと二つのダイアログをこの方法で扱っています。`handle(WheelEvent)` は、中身がスクロールするダイアログのようにホイールを受ける重なりへ、同じ決まりでホイールを渡します。

## フォーカス

`lamina/widgets/focus_manager.hpp`：`FocusManager` は、加えた `Focusable` な部品（`focused()` と `set_focused` を持つもの。入力欄がこれに当たります）の Tab の順を持ちます。フォーカスは部品自身が持つので、入力欄のクリックや Escape はすぐに反映されます。`handle(KeyEvent)` は、Tab で次の部品に、Shift+Tab で前の部品にフォーカスを移し、端では反対の端に戻ります。キーを使ったときは true を返します。どれにもフォーカスがない間は、Tab で最初の部品に、Shift+Tab で最後の部品にフォーカスを移します。Ctrl+Tab はプログラムに任せます。ただし、フォーカスのある部品がタブを受け取るとき（`TabAccepting`。`accepts_tab()` が true のもので、`TextFieldOptions::accepts_tab` にした入力欄が当たります）は、Tab をその部品に任せ、Shift+Tab では前へ移し、Ctrl+Tab と Ctrl+Shift+Tab で次と前へ移します。こうしてキーボードでいつでもその部品から出られます。WinForms と WPF のテキストボックスの `AcceptsTab` と同じ振る舞いで、キーボードが抜け出せなくなる罠を作りません（WCAG 2.1 の達成基準 2.1.2）。`can_focus()` を持つ部品（`FocusGated`）は、それが false を返す間は飛ばします。いまは隠れている部品のためです。`move_focus(direction)` と `clear_focus()` は同じことをコードから行い、`remove(widget)` は部品を順から外し、`clear()` は順を空にします。`suspend()` はフォーカスのある部品を覚えてフォーカスを外し、`resume()` はその部品がまだ順の中にあればフォーカスを返します。入れ子にでき、`clear()` しても覚えたものは残るので、その間にプログラムが順を作り直してもかまいません。`TextInput`（`caret_area()` と `next_blink_seconds()` を持つ `Focusable`）については、`caret_area()` がシステムの IME を開く場所を（`Window::set_text_input` に渡します）、`next_wake_seconds()` が次にカーソルが点滅する時刻を（`Window::wake_after` に渡します）返します。どちらも、フォーカスがない間は空です。`advance(direction)` は `move_focus` と同じように動きますが、端で先頭へ戻らずに止まり、false を返します。そのため、ダイアログが中身の順と操作のボタンをつなぐように、持ち主が複数の順をつなげられます。`has_focus()`・`any_can_focus()`・`focused_bounds()`（`bounds()` を持つ部品のとき）は順の状態を返します。`add_group(manager, shown)` は、別の `FocusManager` を一つの止まり場所として順に入れます。Tab はその中を一つずつたどり、`shown` が false を返す間は飛ばします。ペインの足場のペインはこれで入れます。

`lamina/widgets/focus_indicator.hpp`：操作部品のキーボードのフォーカスです。`Button`、`IconButton`、`Fab`、`Checkbox`、`Switch`、`RadioButton` は `Focusable`（`focused()` と `set_focused`）で、`handle(KeyEvent)` を受けます。フォーカスがある間、ボタン、アイコンボタン（切り替え式なら切り替わります）、FAB は Space か Enter で押され、チェックボックスとスイッチは Space で切り替わり、ラジオボタンは Space で選ばれます。キーで押されたときは true を返します。`handle(PointerEvent)` がクリックで true を返すのと同じなので、プログラムはどちらにも同じように応じられます。Ctrl を伴うキーと、押し続けたときに繰り返されるキー（`KeyEvent::repeat`）では何も起きません。Space を押し続けても、切り替わるのは一度だけです。ウィンドウはキーを離したことを伝えないので、部品はキーを押した時点で動き、押された見た目にはなりません。このフォーカスはキーボードのためのものです。クリックではフォーカスを受けず、部品に届いたポインターの押下では、窓のどこを押してもフォーカスを失います（スクロールバーの上などで、プログラムが部品に届く前に止めた押下では失いません）。そのため、フォーカスの表示は Tab の後にだけ出ます。Compose の focus-visible（※キーボード操作のときだけフォーカスを見せる仕組み）と同じ振る舞いです。入力欄は今まで通りクリックでフォーカスを受け、枠線でそれを示します。フォーカスのある部品は、状態の重ねをフォーカスの不透明度（0.10）に上げ、M3 のフォーカスの輪を描きます。`secondary` の 3 dp の輪を、入れ物、スイッチのトラック、またはチェックボックスとラジオボタンの 40 dp の状態の重ねの円から 2 dp 外側に、その角に沿って描きます（`tokens/focus.hpp`。出典は [docs/design-tokens.ja.md](design-tokens.ja.md)）。輪は速い効果のばねで現れ、消えます。これらの部品が共通に使うのが `FocusIndicator` で、フォーカスを持ち、押されたら手放し、状態の重ねを上げ、輪を描きます。タブの列・ナビゲーションバーとレール・スライダー・メニュー・スナックバーの操作、例の色の丸と折りたたみもこれを使います（それぞれの項を見てください）。`paint_inward` は輪を形の内側に描き、タブ・メニューの項目・折りたたみで使います。

`lamina/widgets/focus_stop.hpp`：`FocusStop` は、ピッカーの日のます目のような複合部品の一部を、`Focusable` で `FocusGated` な `FocusManager` の一員にします。`forward_focus` は、出ているときだけ止まる子の部品のための `FocusStop` を作ります。

## 無効の状態

`lamina/widgets/enablement.hpp`：無効の状態。`Button`・`IconButton`・`Switch`・`Checkbox`・`RadioButton`・`Slider`・`TextField` は、選択肢に `enabled` を取り、`enabled()`・`set_enabled(bool)`・`can_focus()` を持ちます（`Disableable`、`FocusGated`）。タブ・ナビゲーションバーとレールの項目・メニューの項目・まとまりに分けたメニューの項目は、項目ごとに `enabled` を取り（`set_tab_enabled`、`set_item_enabled`）、列には列全体を有効・無効にする `set_enabled` があります。列を有効に戻すと、項目ごとの設定がそのまま生きます。無効な部品はポインターとキーを受けず、押した状態・ポインターの重なり・キーボードのフォーカスを手放し、`FocusManager` はその部品を飛ばします。項目の並ぶ部品は、矢印・Home・End・クリック・アクセスキーで無効な項目を飛ばし、キーボードで開いたメニューは最初の有効な項目にフォーカスを置き、有効な項目のない列は Tab の順から外れます。色は Compose の既定の無効の色です（中身は on-surface か on-surface-variant の 38 %、入れ物は on-surface の 10 % か 12 %。スイッチとスライダーのつまみは surface の上に重ねた色。一覧は [docs/design-tokens.ja.md](design-tokens.ja.md)）。Compose は一度に切り替えますが、lamina-ui は既定の効果のばねで移します。ボタンの高さも、Compose は一度に変えますが、lamina-ui はばねで無効の高さへ移します。`Enablement` が状態と移り変わりを持ち、`resolve(scheme, StateColor)` は `tokens::StateColor`（役割・不透明度・surface の上に重ねるかどうか、または `over` でほかの役割の上に重ねること）を色にします。FAB には Compose と同じく無効の状態がありません。

## 読み上げ

`lamina/widgets/accessibility.hpp`：どの部品も `accessible()` を持ち、`AccessibleNode` を返します。中身は、役割（ボタン・切り替えボタン・チェックボックス・ラジオボタン・スイッチ・スライダー・タブの列・タブ・入力欄・ラベル・メニュー・メニューのまとまり・メニューの項目・ダイアログ・ナビゲーション・ナビゲーションの項目・進み具合の表示・状況の表示・ツールチップ・タイトルバー）、名前、窓の座標での位置と大きさ、状態（有効・フォーカスを受けるか・フォーカスがあるか・オン／オフ／途中・選ばれているか・値とその範囲・モーダル）、当てはまるときの値と説明、項目の並ぶ部品・メニュー・ダイアログ・スナックバー・タイトルバーでは子の節点です。メニュー・ダイアログ・スナックバー・ツールチップは、閉じている間は何も返しません。名前は見えている文字から取ります。見える文字のない部品（アイコンボタン・FAB・アイコンだけのボタン・タブ・ナビゲーションの項目）は選択肢に `accessible_name` が要り、ないと `std::invalid_argument` を投げます。チェックボックス・スイッチ・ラジオボタン・スライダーも選択肢で `accessible_name` を取ります。入力欄の名前はラベルで、ラベルがなければ案内の文字です。値には入力した文字を返します。`WidgetSet::accessible_nodes()` は部品（`Accessible`）の節点を集め、`find_accessible`・`focused_accessible`・`visit_accessible`・`describe` で木を探したり書き出したりできます。タイトルバーは、右上のボタンの名前を `TitleBarOptions::names`（`TitleBarNames`。既定は英語）から取るので、プログラムが訳を渡せます。この仕組みは OS に依らず、まだどの OS の読み上げの仕組みにもつないでいません。

## キーボードショートカット

`lamina/widgets/shortcuts.hpp`：`KeyChord`（キーと Ctrl・Shift・Alt）、それを `lamina/tokens/shortcut.hpp` のプラットフォームの `ShortcutFormat` で書く `format_chord`（Windows と Linux では「Ctrl+Shift+S」、macOS では「⌃⇧S」）、組み合わせ・動作・有効かどうかを持つコマンドを ID で保ち、キーに一致するものを走らせる `ShortcutRegistry`。`FocusManager::claims_key` はフォーカスのある部品がキーを自分のものにするか（テキスト欄のクリップボードと元に戻すキー）を返すので、`handle(event, focus)` はフォーカスが自分のものにしないキーだけでコマンドを走らせます。

## ドラッグ

`lamina/motion/velocity_tracker.hpp`・`anchored_draggable.hpp`・`lamina/tokens/drag.hpp`：シート・ドロワー・レールのドラッグのしくみ。`VelocityTracker` は Compose の最小二乗（`Lsq2`）の速さの測り方です。直近 100 ms のサンプルに式を当てはめ、40 ms 止まるとサンプルを忘れ、いちばん新しいサンプルでの傾きを返します。`AnchoredDraggable<T>` は、名前の付いたアンカーの間の位置を持ちます。`press`・`move`（8 dp の遊びを越えるとドラッグが始まります）・`release`（速さは 8000 dp/s までに抑えます）・`fling`（Compose の `computeTarget`。速さがなければいちばん近いアンカー、速さのしきい値以上ならはじいた向きの次のアンカーで、それ以外は位置のしきい値で決めます）と、ばね（離したときの速さを引き継ぎます）かトゥイーンで動かす `animate_to` があります。サンプルの時刻は `PointerEvent::time_seconds` で渡し、SDL の窓は出来事の時刻からこれを埋めます。
